# CHARACTER ENCYCLOPEDIA v2 — ARCHITECTURE 4 DESIGNS v0.1

Status: `ENCYCLOPEDIC v2 DESIGN COMPARISON / PACKAGE F / NOT CANON`
Date: 2026-08-17
Project: 《우주선에는 인간이 한 명뿐이다》

Goal:
Build a reference-grade character encyclopedia deep enough that ordinary scenes do not invent major personal facts ad hoc, while preserving enough elasticity for 230 episodes and ~14 years of life change.

Existing authority:
`canon/CHARACTER_BIBLE-v1.md`

Must not change locked:
- ages/origins,
- core jobs,
- family chronology,
- major goals/flaws,
- voices,
- PR-H1,
- Amara/household role,
- long arcs,
- forbidden drifts.

---

# DESIGN A — MINIMUM SCENE ANCHORS

For each character lock only:
- appearance sketch,
- home type,
- one hobby,
- one non-plot friend,
- one personal object.

## Strength
- fast,
- flexible,
- low continuity burden.

## Weakness
- still too shallow for reference-grade standard,
- finances/education/health/routine/social network remain improvised,
- 14-year aging underdesigned.

Verdict: `INSUFFICIENT`

---

# DESIGN B — EXHAUSTIVE BIOGRAPHICAL DOSSIER

For each character define:
- exact birthday,
- full childhood timeline,
- every school/job,
- exact income/assets,
- every relationship,
- measurements,
- wardrobe catalog,
- full medical history,
- complete daily timetable.

## Strength
- maximum apparent completeness.

## Weakness
- creates false precision,
- makes 230-episode writing brittle,
- irrelevant facts become pseudo-Canon,
- agents may overuse trivia because it exists,
- later story discoveries require needless change control.

Verdict: `REJECT — OVERLOCKING`

---

# DESIGN C — LAYERED PERSONA ENCYCLOPEDIA

Each character note has four authority layers:

### C0 — Core Lock
Already Canon / story-critical identity and arc.

### C1 — Scene Anchors
Facts worth locking because they recur:
- visual grammar,
- residence class/location,
- commute/routine,
- finance/property band,
- education/career path,
- health baseline,
- taste/hobbies,
- personal objects,
- digital/AI habits,
- 3–6 meaningful relationships,
- ordinary conflict patterns.

### C2 — Controlled Elastic
Defined ranges/preferences, but exact values/names can be chosen when needed.

### C3 — Incidental
One-off details may be generated if they pass Canon/Context Pack checks and do not create new history/relationship obligations.

## Strength
- reference-grade without false precision,
- ideal for Obsidian/context packs,
- supports change over 14 years,
- distinguishes `unknown` from `unimportant`.

## Weakness
- requires disciplined metadata.

Verdict: `BEST BASE`

---

# DESIGN D — SOCIAL NETWORK FIRST

Characters are modeled primarily through:
- households,
- work teams,
- friend groups,
- neighborhood nodes,
- hobby groups,
- recurring support roles.

Individual biography remains lighter.

## Strength
- prevents protagonist-orbit NPCs,
- excellent living-world texture,
- strong recurring supporting cast.

## Weakness
- individual physical/financial/health continuity can still be underdesigned.

Verdict: `ESSENTIAL COMPLEMENT, NOT SOLE MODEL`

# 1. Four Authority Layers

## C0 — CANON CORE
Authority:
`canon/CHARACTER_BIBLE-v1.md` + locked Act/Blueprint facts.

Includes:
- name,
- gender,
- origin,
- start/end ages,
- core occupation,
- core relationships,
- goal/flaw/voice,
- secret/knowledge boundaries,
- major arc,
- hard forbidden drifts.

Package F may not silently alter C0.

## C1 — LOCKABLE SCENE ANCHORS
After Package F Red Team, candidates for v2 freeze:
- stable visual markers,
- broad body type/physical habits,
- home neighborhood/type,
- approximate housing/wealth band,
- commute pattern,
- education/training path,
- career details needed for scenes,
- health baseline / recurring limitations,
- 2–4 hobbies/tastes,
- ordinary media/food/clothing preferences,
- personal interface/AI habits,
- 1–3 personal/material objects with recurring value,
- close non-plot network,
- ordinary week rhythm,
- arrival/future residence direction where story architecture already requires it.

## C2 — CONTROLLED ELASTIC
Examples:
- exact birthday,
- exact salary number,
- exact apartment floor/unit,
- clothing brands/design labels,
- exact café/restaurant names,
- minor childhood anecdotes,
- one-off coworkers,
- precise hobby equipment models,
unless later recurring.

C2 can be selected during episode design without Canon reopening if it fits C0/C1.

## C3 — INCIDENTAL
Small scene texture that creates no durable obligation.
Example:
- what snack a person buys once,
- one stranger's name,
- a temporary weather complaint,
- an unused shirt color.

If repeated or consequential, promote to C2/C1 and log it.

# 2. Required Character Note Schema

Each core/recurrent character should eventually contain:

## Identity / Authority
- IDs / aliases
- C0 source links
- Canon vs C1 vs C2 markers

## Physical Presence
- apparent age / aging pattern
- height band only if useful
- body/build
- face/hair/skin distinguishing cues
- habitual posture/gait/gesture
- voice/speech rhythm
- work-related physical habits
- clothing grammar

## Home / Place
- Habitat / district/neighborhood
- dwelling type/size band
- household composition
- key room/object geography
- commute
- recurring local places

## Money / Property
- income/occupation band
- savings/debt/property direction
- spending priorities
- class/status signals
- financial vulnerability

## Education / Career
- educational route
- qualification/apprenticeship
- prior jobs
- current job mechanics
- likely 14-year career changes

## Health / Body
- ordinary baseline
- chronic issues/injuries if any
- mental-health/coping pattern
- aging changes
- medical privacy boundary

## Culture / Taste
- food
- clothing
- music/media/games/books
- sport/exercise
- religion/ritual or nonreligious stance if relevant
- holidays/comfort routines

## Technology / AI
- personal device style
- AI-assistant use
- privacy attitude
- work-system habits

## Material Culture
- personal objects
- heirlooms
- hobby/work objects
- repair/replacement attitude

## Relationships / Social Graph
- family
- work
- friends
- neighbors
- hobby/community
- people they avoid
- relationship outside main plot

## Ordinary Life
- normal weekday
- free day
- bad day behavior
- how they host/visit/eat/travel

## Knowledge Fence
- what they know at story start
- what they do not know
- sensitive records they can/cannot access

## 14-Year Checkpoints
At minimum:
- start
- after Count/Act4 region
- around Act5/Final Approach pressure
- Act6 long-time bridge
- arrival/ending

## Arrival Future
- ship/orbit/surface preference
- why
- what they lose whichever they choose

# 3. Visual Design Rule

Do not design every character as `attractive future professional in neutral smart clothes`.

The cast needs distinguishable silhouettes through combinations of:
- body proportions,
- age,
- posture,
- grooming,
- color/pattern habits,
- workwear vs civilian wear,
- assistive/medical items where relevant,
- personal objects.

No clothing is a secret origin clue.

---

# 4. Finance Rule

Use **bands and obligations**, not fake exact salaries unless plot requires numbers.

For each adult determine:
- economically comfortable / ordinary / stretched,
- renter/co-op/owner-like occupancy,
- dependents,
- major savings/spending goal,
- whether loss of job/housing would materially hurt.

No core character should be conveniently immune to money unless their actual station explains it.

---

# 5. Home Rule

Core character homes should map onto URB-H1/MAP-H1.

A home note should eventually link:
- civic neighborhood,
- housing band,
- transit node,
- household,
- sensory identity,
- 2–4 recurring objects.

Do not make every protagonist live near every plot institution.
Cross-Habitat travel/commute matters.

---

# 6. Hobby Rule

Every major adult needs at least one meaningful non-work/non-main-theme routine.

Hobby should satisfy:
- can appear in ordinary scene,
- has social or sensory texture,
- does not secretly solve plot,
- can change with age.

Avoid assigning everyone books/classical music/gardening as generic depth markers.

---

# 7. Personal Object Rule

Each core character may have **0–3 high-salience recurring objects**.

Not everyone needs an heirloom.

Object categories:
- ordinary work tool,
- hobby object,
- domestic object,
- inherited item,
- repaired personal device,
- clothing/accessory,
- family item.

Hard rule:
No object becomes a hidden universal lore key unless already in Narrative Device Atlas.

---

# 8. Social Network Rule

For each core adult, target at least:
- 1 household/family tie,
- 1 work tie,
- 1 ordinary friend/community tie,
- 1 mild friction/avoidance tie,
where plausible.

For children/young adults:
- peer relationships are mandatory.

Not every supporting person needs a name immediately.
Only recurring/causal roles are named and given nodes.

---

# 9. Supporting-Cast Tiers

## S1 — Recurring Secondary
Named; own goal/job/home slice; appears across multiple Acts.

## S2 — Recurring Functional
Named; stable role/voice; appears several times; lighter private life.

## S3 — Local Recurring
Neighborhood/work/school/hobby anchor; may recur within one Act or locale.

## S4 — Incidental
One-scene function; no durable dossier unless promoted.

This prevents both disposable-NPC world and 200-person character encyclopedia overload.

---

# 10. Character Autonomy Test

For every C0/C1 character ask:

> If Count/Amara mystery vanished tomorrow, what would this person still want this month?

Must have a nonzero answer.

Examples already Canon-compatible:
- Ella: parent/work/social rebuilding
- Noah: peers/hobby/independence
- Raul: clients/partner/music
- Tomas: institution transition/retirement
- Ines: rehab/service improvement
- Jun: neighborhood/work/co-op
- Amara family: housing/careers/school/family geography.

Maren also needs life outside adjudication/family emergency, which Package F must deepen.

---

# 11. Longitudinal Rule

C1 facts can change through declared checkpoints.

Examples:
- hair/fitness/health changes with age,
- housing can change,
- friend networks shift,
- hobbies deepen/drop,
- career promotion/retirement occurs,
- children become adults,
- personal objects change owner/use.

The encyclopedia should record **trajectories**, not one frozen profile copied for 14 years.

---

# 13. Context Pack Rule

An episode agent receives only:
- POV character's C0/C1 note,
- relevant current checkpoint,
- scene-relevant C2 facts,
- other scene character mini-card,
- knowledge fence,
- relevant relationship state.

Do not feed all 11 biographies into every episode.

---

# 14. Completion Threshold

Package F does **not** require:
- exact birthdays for everyone,
- complete ancestry back to launch,
- every friend named,
- exact wardrobe inventory,
- exact salary account balance.

Package F **does** require that arbitrary ordinary scenes stop demanding major personal invention.

Final tests:
- Random Week Test
- Free Day Test
- Unexpected Expense Test
- Illness/Injury Test
- Hosting/Meal Test
- Friend Call Test
- Work Conflict Test
- 14-Year Aging Test
- Arrival Choice Test
- Character Autonomy Test.
