# CHARACTER — RECURRING SUPPORT NETWORK — 4 DESIGNS v0.1

Status: `PACKAGE F SUPPORTING CAST DESIGN / NOT CANON`
Date: 2026-08-17

Goal:
Build a reusable social world around core cast without:
- disposable one-scene NPCs everywhere,
- hundreds of names,
- every support character orbiting Maren,
- support characters secretly delivering plot truth.

---

# DESIGN A — MAXIMUM NAMED CAST

Name every school friend, coworker, neighbor, doctor and clerk.

Strength:
- encyclopedic appearance.

Weakness:
- reader overload,
- huge continuity burden,
- names become meaningless.

Verdict: `REJECT`

---

# DESIGN B — MINIMUM CORE-ONLY CAST

Keep almost all functions unnamed unless essential to a case.

Strength:
- easy reading.

Weakness:
- world feels generated per episode,
- no reunion/recognition reward,
- characters lack independent social lives.

Verdict: `REJECT`

---

# DESIGN C — ONE SUPPORT CHARACTER PER CORE

Each core gets a single friend/coworker.

Strength:
- manageable.

Weakness:
- support becomes obvious emotional utility slot,
- real social networks are richer/overlapping.

Verdict: `INSUFFICIENT`

---

# DESIGN D — LOCALE / FUNCTION PODS + SELECTIVE CROSSOVER

Create small recurring pods:
- Vale school/family/co-op
- Okoro water/school/logistics
- Continuity/legal/archive
- Old Quarter/co-op
- culture/hobby/community

Only S1/S2 people get stable names and mini-goals.
S3/S4 remain role labels until recurrence promotes them.

Strength:
- organic recurrence,
- manageable names,
- supports Obsidian graph,
- lets one support character connect multiple cores naturally.

Verdict: `SELECTED BASE`

---

# SELECTED MODEL — SUP-H1

# `Locale/Function Pods + 12–18 High-Value Recurring Supports + Promotion-on-Recurrence`

Target:

Additional names may exist, but do not front-load them into the Bible unless they recur.

# SUPPORT CHARACTER RULES

Every S1 must have:
- one independent goal/pressure,
- one relation outside the core character when plausible,
- a reason to recur,
- a limit on what they know.

No S1 exists only to:
- explain lore,
- praise/criticize protagonist,
- deliver a clue,
- be an easy victim,
- represent a demographic thesis.

---

# COLLECTION / RECOGNITION PAYOFF

Support recurrence can create non-mystery collection pleasure:
- reader recognizes Sami at a later water crisis,
- Sana later owns Old Quarter work decisions,
- Toma grows away from Noah and reappears,
- Jae's co-op pressures evolve,
- Sorin's archive role changes from ordinary cleanup to Count verification,
without every recurrence being foreshadow/payoff.

Hard distinction:
**recognition return ≠ Chekhov device automatically.**
