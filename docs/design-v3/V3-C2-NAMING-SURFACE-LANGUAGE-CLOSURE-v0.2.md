- Korean readability,

# 4. Korean reader-facing addressing rule

If `루카스 베르너` is later approved:

Primary reader-facing call name:
# **루카스**

Use:
- narration after first introduction: `루카스`,
- colleagues: usually `루카스`, role/title only when natural,
- Mira: `루카스`,
- family: Korean-localized kinship/dialogue grammar + `루카스` where name is needed,
- emergency radio/report: role or full name only if disambiguation is necessary,
- formal records: `루카스 베르너`.

Do NOT casually alternate `루카스` and `베르너` as if both are ordinary call names.

`베르너` should mainly appear in:
- formal report,
- registry,
- first introduction,
- institutional third-person reference if context requires.

This rule remains regardless of which final full name wins: pick ONE reader-facing call name and hold it.

# 5. Family-address translation rule

Korean prose is a reader translation of Meridian Common.
Therefore natural Korean kinship terms may be used for clarity:
- 아버지 / 아빠 according to intimacy,
- 어머니 / 엄마,

- 조카,
without implying Korean ancestry.

Do not invent future kinship vocabulary unless a family structure requires a new concept.

# 7. Payment/resource vocabulary — final C2 candidate

- `크레딧`,
- `잔액`,
- `결제`,
- `가격`,
- `예약`.

- `배정`,
- `우선배정`,
- `사용 슬롯`,
- `승인`,
- `운송용량`,
- `의료수용`,
- `전력/열용량` as context demands.

Crisis-only or politically loaded:
- `배급` only when ration-like policy is actually active,
- `통제`, `봉쇄`, `우회`, `격리` as operational terms.

Hard:
- never use `포인트` as generic currency,
- do not call strategic capacity `돈으로 사는 것`,
- route tags/tokens are not currency,
- no crypto/blockchain vocabulary without a separate story need.

# 9. Model-code policy

Internal production documents may use model IDs.
Ordinary prose normally does not.

Preferred prose:
- `구형 크롤러`,
- `현행형 터그`,
- `구조형 모듈`,
- `정착용 개조 프레임`.

A model code appears only when two near-identical technical variants matter to the scene.

No model name = status/power/rarity.
