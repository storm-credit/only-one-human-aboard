# Narrative Map Architecture — 4 Designs v0.1

Status: `DESIGN COMPARISON / PACKAGE G / NO PROSE`
Date: 2026-08-17
Project: 《우주선에는 인간이 한 명뿐이다》

## Purpose

The project already has:
- 7 Acts / 23 Sub-Acts / EP001~230,
- Information Ladder,
- Foreshadow / Payoff Ledger,
- Deep Cards,
- POV maps,
- Canon dependency harnesses.

Missing layer:
**a single navigable map that tells a writer/agent what narrative devices, canon rules, characters, clues, open loops, payoffs and future constraints are active for one Act/Sub-Act/Episode.**

The target must work both as:
1. a human-facing Obsidian graph/MOC,
2. an agent-facing minimal Context Pack selector.

---

# Design A — Pure Hierarchical Act Tree

Structure:
`Series → Act → Sub-Act → Episode`

Each episode inherits parent context.

Strengths:
- simple,
- readable,
- obvious progression,
- good for episode planning.

Weaknesses:
- a MacGuffin planted in Act 1 and paid in Act 4 is hard to inspect globally,
- character/device cross-links are secondary,
- easy to duplicate notes.

Verdict:
`GOOD SKELETON / INSUFFICIENT GRAPH DEPENDENCY`

---

# Design B — Device-Centric Knowledge Graph

Structure:
Each narrative device is a node.

Example:
`MG-02 Ella Preference Record → plant EPs → reinforce EPs → payoff EP117 → aftershock EP120`.

Strengths:
- excellent for Chekhov/foreshadow/MacGuffin tracking,
- catches abandoned setup and premature payoff,
- natural Obsidian backlinks.

Weaknesses:
- poor serial reading order,
- writer opening EP117 still has to assemble a usable packet manually,
- can become a giant graph with no hierarchy.

Verdict:
`ESSENTIAL CROSS-LINK LAYER / NOT PRIMARY NAVIGATION`

---

# Design C — Episode-First Context Manifest

Structure:
Every episode owns a manifest:
- POV,
- active Canon,
- current characters,
- current locations,
- active devices,
- previous carries,
- future constraints,
- forbidden reveals.

Strengths:
- ideal for LLM/agent context retrieval,
- smallest possible prompt packet,
- excellent drafting safety.

Weaknesses:
- 230 manifests are expensive to maintain manually,
- global structure can disappear,
- duplication risk if the same device is copied instead of linked.

Verdict:
`BEST EXECUTION INTERFACE / NEEDS PARENT GRAPH`

---

# Design D — Dual-Layer Narrative Atlas + Context Manifests

Structure:

Layer 1 — hierarchical navigation:
`Series MOC → Act MOC → Sub-Act Map → Episode`

Layer 2 — cross-linked semantic nodes:
`Device / Character / Rule / Location / Information / Payoff / Open Loop`

Episode Context Pack is generated by following links rather than copying full bibles.

Strengths:
- best human navigation,
- best Obsidian graph use,
- best agent retrieval,
- avoids full-setting prompt dump,
- enables automated QA.

Weaknesses:
- requires stable IDs and link discipline,
- initial migration cost is higher.

Verdict:
`SELECTED BASE`

---

# Selected Architecture — NAM-H1

Name:
**NAM-H1 — Hierarchical MOC + Cross-Linked Device Atlas + Episode Context Manifest**

Rules:
1. Act/Sub-Act/Episode hierarchy controls story order.
2. Device nodes control setup/reinforce/trigger/payoff/aftershock dependencies.
3. Canon nodes remain source-of-truth; maps never duplicate or silently redefine Canon.
4. Episode manifests reference only relevant nodes.
5. Every future payoff must expose its required setup dependencies.
6. Every planted high-salience device needs a payoff state: `OPEN / PARTIAL / PAID / ABANDONED-BY-DESIGN`.
7. Most ordinary details stay untracked as clues to preserve noise.
8. No device quota per Sub-Act; the map audits density but does not force a trick into every block.
9. Exact episode linkage must defer to active Blueprint/M1/POV authorities when conflicts exist.
10. Obsidian graph is a navigation surface, not Canon authority.
