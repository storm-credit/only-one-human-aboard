## 0. Purpose

This phase does not redesign the plot or ontology.
It builds a controlled reference library for the already-designed IP so that characters, craft, equipment, backgrounds and material culture become visually distinct, memorable and collectible without becoming derivative.

Core objective:

> `수집 → 분해 → 비교 → 합성 → 유사성 검사 → 작품 고유 규칙으로 재작성`

A reference is never a design answer by itself.

# 1. Seven collection tracks

## R1 — Character / Human Visual Identity
Collect for:
- face geometry,
- age texture,
- body proportions,
- hair mass,
- posture,
- work-vs-private silhouette,
- fatigue/injury states,
- costume construction.

Do NOT collect one actor/character as a whole template for one Meridian character.

## R2 — Craft / Vehicle / Machine Ecology
Collect for:
- function-readable silhouettes,
- tool/cargo placement,
- maintenance access,
- generation variants,
- wear,
- modular interfaces,
- scale cues.

Target families include crawler, mapping drone, utility tug, rescue skiff, work frame, Outer-Ark servicing craft, deployment barge, lander and surface utility vehicle.

## R3 — Equipment / Props / Professional Tools
Collect for:
- grip/use logic,
- storage/carry,
- safety markings,
- certification wear,
- manual redundancy,
- medical/structural/logistics/security role differentiation.

No all-purpose sci-fi scanner.

## R4 — Background / Architecture / Civic Space
Collect for:
- geometry,
- ceiling/vertical scale,
- traffic flow,
- surface wear,
- signage,
- lighting,
- sound-producing infrastructure,
- crowd use,
- emergency transformation.

Locations must remain one city, not game biomes.

## R5 — Outer Ark / Macro Infrastructure
Collect for:
- shielding,
- thermal rejection,
- service access,
- robotics,
- propulsion separation,
- fabrication/cargo geometry,
- long-duration repair logic.

Current v3 rule:
experienced Meridian is NOT a one-to-one macroscopic map of the physical Outer Ark.

## R6 — Civilian Material Culture
Collect for:
- ordinary clothing,
- bags,
- home objects,
- furniture,
- food/service containers,
- children’s objects,
- hobby miniatures,
- repair/reuse culture,
- personal customization.

Most civilian objects never become clues.

## R7 — Collectibility / Recognition / Lineage
Collect not for appearance alone but for:
- family resemblance between generations,
- old/new tradeoffs,
- local modifications,
- ownership wear,
- standardized interfaces,
- descendant designs in Act9.

Story pattern:
`Encounter → Recognition → Recontextualization → Transformation / Persistence / Loss`.

# 2. Reference-source families

Use multiple media because each solves a different problem.

## Film / live-action TV
Best for:
- age realism,
- body diversity,
- fabric behavior,
- ordinary clutter,
- spatial credibility,
- workwear that looks inhabited.

## Animation / comics / manga
Best for:
- silhouette differentiation,
- readable pose,
- shape language,
- visual memory,
- economy of design.

## Games
Best for:
- repeated object recognition,
- navigable spatial identity,
- equipment families,
- model variation,
- wear and functional readability.

## Real industrial / medical / transit / robotics references
Best for:
- actual access logic,
- joints,
- safety markings,
- maintenance clearances,
- wear,
- hand use,
- role-specific equipment.

## Concept art / production design documentation
Best for:
- seeing iteration rather than copying the final result,
- understanding what requirements produced the design.

# 3. Mandatory decomposition rule

Every selected reference entry must record:
1. `BORROW` — the specific principle worth studying.
2. `DO NOT BORROW` — iconic forms/details that must not be copied.
3. `WHY` — why the principle fits Meridian.
4. `COLLISION` — which existing character/craft/place it could become too similar to.
5. `STORY USE` — where/when the resulting design appears.
6. `SOURCE TYPE` — game/film/anime/manga/real engineering/etc.

No entry without this decomposition can become a design input.

---

# 4. Anti-copy synthesis rule

For a HIGH-memory final element:
- use at least **3 reference sources from at least 2 different media families**,
- whenever mechanical/architectural function matters, include at least **1 real-world functional reference**,
- no single source may define face + costume + pose + equipment together,
- no iconic logo, exact color blocking, weapon arrangement, helmet profile or vehicle nose is transferred.

The output must be redescribed in Meridian’s own functional language before visual design Freeze.

---

# 5. Source-dominance cap

To prevent `this is basically X`:
- no single entertainment IP should account for more than ~20% of HIGH-memory reference decisions,
- no final craft family should be primarily derived from one franchise,
- no core character uses a single identifiable performer/character as dominant face reference,
- real occupational/industrial references should be present across every practical-design track.

---

# 6. Character anti-same-face protocol

Before final faces are generated/illustrated, each core character receives explicit values for:
- facial length,
- jaw width,
- cheek structure,
- nose mass/profile,
- eye spacing/shape,
- brow weight,
- age texture,
- hair mass,
- body center-of-mass impression,
- posture,
- height band,
- habitual hand position.

Hard gate:
If two core characters remain recognizable only because of hair/color/clothes, the face design FAILS.

Run tests in:
1. grayscale,
2. bald/head-covered state,
3. same neutral clothing,
4. small silhouette,
5. side/3-4 profile.

---

# 7. Machine anti-same-craft protocol

Each HIGH craft family must differ on at least 3 function-derived axes:
- mass distribution,
- locomotion/anchoring,
- operator/cargo center,
- manipulator layout,
- access doors/panels,
- sensor mast placement,
- payload frame,
- service interface.

Color alone never distinguishes craft families.

---

# 8. Background anti-biome protocol

Each major zone needs a distinct readable combination of:
- geometry,
- density,
- motion,
- light source behavior,
- material age,
- public/private use,
- acoustic signature,
- landmark.

But at least 2 common city standards must recur everywhere:
- signage/wayfinding family,
- safety/utility interface family,
- common construction/repair standards.

This preserves `one Meridian`.

---

# 9. Collectibility rules

Collectibility comes from recognition and history, not rarity color or power.

Allowed:
- generation changes,
- repair marks,
- certification history,
- localized modifications,
- discontinued but still useful interfaces,
- ownership transfer,
- descendant settlement designs,
- in-world miniatures/hobby culture.

Forbidden:
- S/A/B tiers,
- legendary/epic rarity language,
- new model = automatic upgrade,
- all old equipment = superior craftsmanship,
- signature hero vehicle that turns story into pilot/mecha franchise,
- object introduced only to become merchandise.

---

# 10. Reference storage policy

Repository stores:
- source title,
- creator/studio/publisher where useful,
- source URL or bibliographic locator,
- description of the studied principle,
- borrow/avoid notes,
- Meridian mapping.

Do NOT mirror copyrighted reference image libraries into the repository by default.
Use external source links and legally available/public production-design pages.
Local original concept art can be stored later.

# 11. Initial research directions — selected hybrid

## Direction A — Function-First Industrial Realism
Study pool:
- Hardspace: Shipbreaker,
- Planetes,
- NASA robotic servicing / industrial robotics,
- The Expanse production design.

Use for:
craft, workspaces, professional tools.

## Direction B — Lived Civic Material Realism
Study pool:
- Andor/Ferrix costume and material logic,
- Alien: Isolation environmental constraint method,
- Planetes ordinary worker life,
- real transit/hospital/industrial public spaces.

Use for:
citizens, Midring, Belt, Med, Juno space, ordinary clutter.

## Direction C — Strong Recognition Without Uniformity
Study pool:
- Arcane character iteration/body-type diversity,
- Spider-Verse silhouette/line/shape readability,
- live-action adult faces for grounding.

Use for:
core cast differentiation only.

## Direction D — Material Lineage / Collector Recognition
Study pool:
- Hardspace class variants and modular remix logic,
- actual industrial product generations,
- maintenance/certification practices,
- current 15-chain Meridian collection overlay.

Use for:
`같은 계열임을 알아보지만 동일하지 않은` machines/objects.

### Selected blend
**A + B = base**
**C = character readability layer**
**D = collectibility/return layer**

No one source defines the whole art direction.

# 12. Workflow

For each track:
1. gather 8~20 broad references,
2. reject obvious aesthetic-only matches,
3. decompose selected references,
4. map to existing Meridian function,
5. run collision matrix,
6. produce 3~4 Meridian synthesis directions,
7. Red Team,
8. select one hybrid,
9. only then generate/draw original concept sheets,
10. update exact episode/material return overlay where needed.

---

# 13. Freeze conditions

Reference phase can close only when:
- core cast same-face matrix passes,
- HIGH craft families pass silhouette/function test,
- Midring/Belt/Garden/Med/Old Works remain distinguishable without color labels,
- Outer Ark design remains physically/story coherent,
- source-dominance audit passes,
- 15 existing return chains remain story-first,
- at least 30~40% of sampled ordinary props are explicitly `NO PAYOFF / ORDINARY NOISE`,
- no new major ontology or plot is introduced merely for visual appeal.
