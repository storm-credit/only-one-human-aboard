# 1. Attack — Act1 becomes slice-of-life filler

Risk: HIGH if the new ordinary-life anchors are treated as standalone filler.

Why patch survives:
- F1 work puzzles preserve concrete problem-solving,
- F2 relationship choices create durable state change,
- F3 city-life anchors create attachment but are not sufficient alone for every episode,
- each density band still requires a local practical payoff.

Execution lock:
**An ordinary-life scene must either deepen attachment to a recurring person/place/routine or change a relationship/work state.**
Pure atmospheric filler is not protected merely because Act1 needs normal life.

Additional lock:
By EP014, reader must already have received one complete work/rescue payoff.
By EP028, reader must have received at least three distinct local payoff types: technical, social/relationship, ordinary-city.

Verdict: PASS.

# 6. Attack — Act7~8 remove so much explanation that reader becomes lost

Risk: HIGH.

This is the main counter-risk created by the patch.

Repair selected:
Use **evidence-first + bounded synthesis**.

Rule:
After roughly every 6~8 episodes of accumulating evidence, allow one concise synthesis beat where characters state:
- what is now strongly supported,
- what remains hypothesis,
- what action changes because of that distinction.

Hard:
Synthesis cannot introduce a new fact unsupported by prior scenes.
It should be shorter than the evidence sequence it summarizes.

Reader-facing hierarchy:
1. `what happened to this person/system now`,
2. `what evidence changed our model`,
3. `what we currently think it means`.

Verdict: PASS WITH SYNTHESIS LOCK.

# 13. Brainstorming policy after this pass

## Targeted brainstorming
Allowed only when one of these concrete failures appears:
- an episode has no local reward,
- a reveal cannot be dramatized without lecture,
- two consecutive arcs repeat the same incident flavor,
- a relationship payoff lacks prior movement,
- a science/medical fact fails verification,
- prose sample proves pacing/fun weaker than blueprint predicts.

No brainstorming merely because `maybe we can add something cooler`.

# 14. User-question policy

No further deep-design interview is needed before finishing prewriting preparation.

Questions should be reserved for **authorial taste choices** that cannot be inferred safely and are costly to reverse in prose:
- protagonist final name,
- exact naming flavor of districts/family,
- romance explicitness/endpoint surface,
- violence/gore presentation ceiling,
- final prose tone if multiple equally valid options remain.

These are C2/Tone decisions, not architecture blockers.

Therefore generic continuation should proceed without asking the user repeated worldbuilding questions.
